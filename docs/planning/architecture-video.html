Scene 2

What's novel — four boundaries that standard agent frameworks don't draw

Pillar 1

Deterministic 13-rule Critic

Code-level validation over every LLM output. No "LLM-as-judge" — 13 Python rules, each deterministic, each returning a pass/fail with a corrective instruction for retry.
Novel stress-tested against a published no-persistence scenario to prove the Critic isn't rubber-stamping LLM positive-finding bias.
Pillar 2

Evidence splitter

In DFIR the adversary authors the evidence — a filename or registry value can carry prompt-injection payload. Tool output is parsed server-side: raw bytes to the ledger, structured fields to the agent.
Novel defending prompt injection at the evidence boundary, not the prompt boundary.
Pillar 3

Tokens bound to plan

Every tool call carries an HMAC-signed permission slip scoped to (case, tools, paths, plan_digest, expiry). MCP server refuses anything outside scope.
Novel the plan_digest binding — tokens die when the plan changes, so they can't be replayed across plans.
Pillar 4

Linear hash chain

Each ledger entry embeds SHA-256 of the previous entry. Ledger lives outside the case folder. A companion replay tool walks the chain and passes or fails loudly.
Novel tamper-evidence by construction, with separate-ledger storage that defeats self-attestation.

MCP server the "tools" process
runs fsstat · fls · icat · regripper · tasks
verifies capability tokens · splits evidence output
shared mount /cases/<id>/ — forensic disk image, read-only bind mount
↓  audit writes leave the container boundary  ↓
outside the container integrity ledger — append-only, SHA-linked, on a separate volume so the container can't silently rewrite its own audit trail.
Caveat same-container deployment means tokens are application-layer, not cryptographic. The evidence splitter (Pillar 2) carries the real injection defense — if injection never reaches the agent, hijack can't happen.
