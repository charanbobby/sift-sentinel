Sift Sentinel is an autonomous AI agent for digital forensics. Built for the SANS Find Evil 2026 hackathon. This page is your map into the live submission. Every link below opens a working artifact, not a screenshot.

The headline differentiator
Sift Sentinel hunts for attackers who use AI themselves on a compromised host: local LLM inference servers planted as persistence, prompt-injection payloads buried in attacker-controlled registry values and scheduled tasks, and the operational fingerprints of AI-assisted reconnaissance. The agent is also architecturally prevented from going rogue (no shell primitive, capability tokens on every tool call) and a deterministic 17-rule critic with no AI in its loop checks every claim before a human sees it.

What the numbers mean, and what they do not. The 1.00 precision and recall claim is on the one case with a third-party answer key. Other cases come with weaker ground-truth claims: project-owner annotation against community write-ups, sampled review with citation verification, or the daily-loop synthetic plants where the answer key is known by construction because the team planted them. The "zero fabricated findings" claim is verified end to end across all 32 reviewed runs; two data-quality issues (one malformed citation pointer, one rationale-text hallucination on a real-finding case) are logged separately in the accuracy report rather than swept. Every committed finding in the run viewer surfaces its cited evidence with a unique tool-call id, so judges can self-audit any claim by clicking into a case.

How the submission lands against the judging criteria

The contest's six judging criteria are equally weighted with Autonomous Execution Quality as the tiebreaker. Here is where each criterion is best demonstrated.

1. Autonomous Execution Quality (tiebreaker)
accuracy report Section 4 · run viewer
Five-stage pipeline with named human gates, retry budget, deterministic critic that catches the agent's mistakes, daily-loop self-validation against fresh threat intel, integrity ledger that hash-chains every plan to every tool call to every finding. Self-correction is rule-based and audit-traceable, not unstructured LLM retry.
2. IR Accuracy
accuracy report Sections 0, 1, 5
Zero fabricated findings across 32 reviewed runs. 1.00 precision and recall on the externally-validated case. Two data-quality issues caught and logged honestly rather than swept. Cross-host campaign signatures (the SRL-2018 dual masquerade families, the SRL-2015 svchost Run-key signature) are independently corroborated across multiple hosts.
3. Breadth and Depth of Analysis
accuracy report Section 3 (eleven per-case sections)
Depth on persistence detection across both SANS datasets plus three publicly-available cases plus six days of synthetic intel-driven scoring. Disk-only, dual-channel, and memory-only sweeps. The strongest fileless persistence finding in the corpus (a registry-resident PowerShell payload masquerading as a vendor key) is named and cited in the per-case write-up.
4. Constraint Implementation
architecture diagram · accuracy report Section 4
Four trust boundaries, all architectural rather than prompt-based. The MCP server has no shell primitive. Every tool call carries a capability token bound to a path scope and time-to-live. A prompt-injection scanner quarantines evidence records before they reach the analysis LLM. Each guardrail has been tested for bypass through production runs (13 critic catches, 9 capability denials in the memory-only sweep, 11 quarantines across 46 reviewed runs); accuracy report Section 4 documents the bypass evidence.
5. Audit Trail Quality
run viewer · LangFuse traces
Per-case run folder with the typed plan, evidence records as JSONL, structured findings with cited tool-call ids, the critic-disagreement log, and an integrity ledger that hash-chains plan to call to finding. Every LLM call is also traced to LangFuse with token counts and per-call cost grouped by per-run session. A judge can drill from any finding back to the exact tool execution and the LLM tokens that produced it.
6. Usability and Documentation
README · this site · runbooks
Live deployment at sentinel.sshub.dev. Docker compose one-liner for local install. README with the AI architecture overview, the four trust boundaries, the four LLM call sites with cost shape, and the SIFT Workstation note. Per-case review notes for every curated case under docs/submission/.
